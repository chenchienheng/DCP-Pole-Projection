# External Ecosystem Learning & Absorption Schema R2 (Proposal)

> Candidate replacement for the earlier node-first absorption proposal.
> This public repository is a DCP-oriented projection carrier, not a Native Source Root, runtime, Canon, or authority root.
> External material is first a Signal / Specimen. Similarity to CoreTri/NFN does not establish admission, adoption, authority, or truth.

## 1. Why R2 exists

The earlier proposal mapped named external nodes directly into AXIS roles. That remains useful as historical lineage, but it can create confirmation bias: an external system is interpreted through the existing framework before its own operating world, success mechanism, trade-offs, and failures are reconstructed.

R2 reverses the order:

```
External World
→ ACTUAL_READ
→ Whole-Specimen Reconstruction
→ Native Success Mechanism
→ Failure / Trade-off / Boundary
→ Counterfactual Challenge
→ NFN/CoreTri Mapping
→ Candidate Extraction
→ Bounded Experiment
→ Effect / Evidence
→ Native Return
→ Structural Nutrient
→ Metabolism / Rejection / Replacement
```

Forbidden shortcut:

```
External → "looks like NFN" → extract feature → claim absorbed
```

## 2. Whole-specimen intake

For each material specimen preserve, when supported by evidence:

- specimen identity, source, version/date, observation time
- original problem and user/operator context
- complete action chain, not only the highlighted feature
- representation and interaction model
- execution/orchestration model
- verification and evidence model
- failure recovery and stopping conditions
- data / authority / security / privacy boundaries
- deployment / maintenance / economics when actually evidenced
- success mechanism
- failure modes and trade-offs
- UNKNOWN for unsupported fields

Availability, searchability, or a secondary summary does not equal ACTUAL_READ.

## 3. Anti-confirmation gate

Before mapping a specimen into CoreTri/NFN, answer:

1. What does it have that the current XuanLing ecosystem does not?
2. Where is the external specimen materially more mature?
3. Does it refute, weaken, simplify, or replace an existing design?
4. What is lost if it is not adopted?
5. What dependency, cost, risk, lock-in, or authority burden appears if adopted?
6. Is there a simpler mature external capability that should be reused instead of rebuilt?

If every answer collapses to "XuanLing already has this", mark:

`CONFIRMATION_RISK = HIGH`

and do not promote the specimen to Structural Nutrient.

## 4. Comparison dimensions

Map only after the whole-specimen and anti-confirmation passes.

Dimensions:
- Reality / Subject
- Need
- Identity
- Authority
- Evidence
- Representation
- Skills / Capability
- Carrier / Tool / Model
- Action

- Return

Allowed comparison values:
`SAME | PARTIAL | DIFFERENT | SUPERIOR_EXTERNAL | SUPERIOR_XUANLING | UNKNOWN`

"Isomorphic to NFN" is not a sufficient conclusion.

## 5. Nutrient classes

### 5.1 Representation / Workbench Nutrient
A better way to make the same Reality readable, editable, or operable.

Guard:
`Layout Edit != Semantic Edit != Reality Mutation`

Examples may include flow, sequence, state, ER, C4, Gantt, Sankey, journey, 3D/BIM, evidence, and simulation projections. A renderer is replaceable; the stable subject and lawful relations are not silently rewritten by layout changes.

### 5.2 Action / Composition Nutrient
A demonstrated improvement in orchestration, exploration, model/tool selection, context retention, verification, failure recovery, or observation-driven recomposition.

Question:
Does new Observation / Evidence actually change the next lawful composition?

### 5.3 Structural / Core Nutrient
Only a structure that survives counterexamples and bounded experiments, and is reusable beyond one private/company/project body, may become a candidate structural nutrient for XuanLing/CoreTri.

Useful private content does not become core material merely because it helped the experiment.

## 6. Skills as a bidirectional learning mesh

Skills is not merely a tool catalogue or a gap-filling function.

External direction:
- locate and ACTUAL_READ specimens
- reconstruct how the external system actually works
- preserve success mechanism, limits, cost, failure, and dependencies
- qualify reuse versus rebuild

Internal direction:
- identify materially affected Living / GLModel / Qinyi / CoreTri / XuanLing relations
- create reversible candidates
- select the smallest meaningful experiment
- collect Effect / Evidence / Failure
- return only lawful, minimal, generalizable structural nutrient

Skills does not acquire source ownership, Native Authority, acceptance authority, or public-release authority by performing this mapping.

## 7. Living World workshop implication

Living World is not a 3D component shop. It is a place where Reality can be worked.

Need-relative workbench families may include:
- spatial / 3D / BIM
- object / relationship
- flow / process
- state / transition
- sequence / interaction
- timeline / Gantt
- data / ER
- cost / supply / lifecycle
- document / evidence
- simulation / scenario
- journey / experience
- validation / comparison

These are not a permanent module roster. One stable Subject may have multiple projections without becoming multiple truths.

## 8. GLModel implication

GLModel is not a copy of the XuanLing core model. It carries model capabilities that may be distributed, specialized, replaced, or user-held within lawful scope.

When a mature external capability is better, replacement is allowed. Replacement must preserve or explicitly requalify Identity, Authority, Evidence, Return, and Recovery.

## 9. Root / affected-return rule

Root must not broadcast "everyone research this."

Only a material cross-domain delta may form a bounded cycle:

```
ACTUAL_READ
→ fresh affected-set
→ bounded pointer broadcast
→ receiver USE / NO_MATERIAL_EFFECT / HOLD / CANNOT
→ Material Return
→ reconcile
→ dissolve
```

Suggested Material Return:
- Need
- Native
- Specimen
- What changed
- Actual Effect
- Evidence
- Counterexample / Failure
- Structural Nutrient
- Authority Boundary
- Unresolved Residue
- Re-entry

## 10. Regression specimens

### SuperMermaid-like enterprise visual editor
Do not reduce to "Mermaid renderer".
Compare at least:
- enterprise pattern library
- multi-representation projection
- direct manipulation / drag editing
- text/code/URL intake
- layout vs semantic editing
- learning cost
- export / interoperability
- round-trip fidelity
- template generalization

### Antares-like AI-assisted security research
Do not reduce to "adaptive composition".
Compare at least:
- orchestration
- observation-driven replanning
- tool/model selection
- context retention
- verification
- failure recovery
- human control and human hunches
- authorization scope
- evidence preservation
- stopping conditions

Unsupported properties remain UNKNOWN.

## 11. Acceptance criteria

R2 is not accepted merely because this document exists.

At least:
1. one specimen preserves materially more of the complete action chain and trade-offs than the old feature-extraction method;
2. one external result modifies, simplifies, replaces, or retires an existing XuanLing design rather than only adding another layer;
3. one mature external capability is reused or substitutes for a local rebuild candidate;
4. one candidate produces observable Effect in Living / GLModel / Skills;
5. a failed or rejected specimen still produces useful evidence/nutrient;
6. Root does not create all-participant work merely because an external signal was interesting.
