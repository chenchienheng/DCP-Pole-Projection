# Abundance under constraint — useful growth within the actual task

Status: CANDIDATE_REFERENCE / NOT_RUNTIME / NO_NEW_AUTHORITY.
Batch: BATCH_FIELD_CONTINUITY_UPTAKE_20260928 (Asia/Taipei).

## Purpose and operating principle
Constraints define which useful actions can be composed; they are not a reason to reduce every authorized task to repeated small maintenance. Advance the original deliverable far enough to become usable, reusable or recoverable. A small change is appropriate when sufficient, not because a fixed patch size is an architectural goal.

Keep the distinction between purpose, available capability, actual authorization, risk and evidence. More models, files or connected tools do not automatically expand the permitted action. Equally, one unavailable tool or one local HOLD does not cancel independent authorized work.

## Expansion modes
Read-only analysis, artifact construction, code repair, source reconciliation and candidate preparation may be combined when the current task authorizes them. A label such as Low_Risk does not authorize a new scan, external disclosure, issue, branch or account change. Select the smallest sufficient set of effects and resources, not the smallest number of edits regardless of outcome.

For higher-impact changes, preserve the actual decision boundary before execution. Reversibility and a later receipt do not replace prior approval where approval is required. New deployment, payment, access changes and publication each need their own scope; tool availability is not that scope.

## Retain uncertainty without freezing progress
A weak signal can remain a traceable candidate; do not delete it merely because it is weak. Radar, Pending and Candidate were local descriptive labels, not a universal ranking or retention order. Record what the material can and cannot support, the source and applicable version, and the actual condition for revisiting it. A known unmet condition holds only the dependent operation.

## Relationship to other work
The dependency, initiative, knowledge-unit and recomposition references are optional complementary views. They do not require a fixed axis, orbit, commander or MotherTree hop. Keep the original subject and useful results across recomposition; do not create a new task merely to represent the same work in another document.

## Return and completion
Return the material effect to the original deliverable and its affected receiver. Distinguish an idea, a saved candidate, a performed action and an accepted outcome. State the remaining gap specifically rather than reopening completed diagnostics. Unchanged applicable evidence can be reused; no universal all-domain sweep or acknowledgement gate follows from this principle.
