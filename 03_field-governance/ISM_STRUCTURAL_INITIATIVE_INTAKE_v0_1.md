# Structural initiative — act within prior authority, not from silence

Status: CANDIDATE_REFERENCE / NOT_RUNTIME / NO_NEW_AUTHORITY.
Batch: BATCH_FIELD_CONTINUITY_UPTAKE_20260928 (Asia/Taipei).

## Purpose
Preserve the useful initiative model as a non-core decision aid: recognize an unresolved obligation, choose a permitted action or hold the dependent step. It does not create a separate will-bearing actor, permanent commander, or new source of authority.

## User availability and authorization
Reduced user availability does not widen authority. Urgency, low risk, reversibility and a declared responsibility cannot substitute for an actual grant. When original work is already authorized and independent of an unanswered decision, continue it rather than ask the user to approve every small edit. When a required decision is unresolved, hold that effect and state the missing condition.

## Retained components
Structural_Tension identifies a real unsatisfied dependency, not an automatic escalation. Authorization_Topology describes the applicable action boundary, not a fixed actor tree. Risk_Layering separates constraints from priority. Minimal_Value_Model compares eligible options without claiming a universal optimum. Retroactive_Acknowledgement makes an already authorized action reviewable; it never retrospectively grants permission for an unauthorized one.

## Proactive action and local stop
Choose a coherent sufficient batch inside the authorized deliverable. Reading, drafting, classifying a PR or creating a candidate file are not universally permitted simply because an old list called them low-risk. Conversely, an external permission HOLD is not a reason to stop unrelated local construction.

Private/public judgments, new access, irreversible changes, core changes and resource commitments retain their own approval requirements. If an operation's result is unknown after interruption, inspect effects before retrying. Do not infer execution failure or permission from silence.

## Return
Use the existing Initiative_Return_Record form to identify the trigger, actual action, boundary, reversibility, unresolved decision and return. Record evidence and applicable source/version with the outcome; Next_Task does not become an automatic dispatch. Delivery and receiver use stay distinct. No new scheduler, external service or standing authorization is introduced.

## Retained compatibility forms

These uninstantiated source forms preserve compatible field names for a selected profile, not a required global schema or action grant. BASE/QIN, Window/Rank, named tables, mandatory_fields and destinations apply only to that explicitly chosen profile; do not create resources or infer approval to fill a form.
